# 拼车小程序 - 发布体验优化设计文档

**日期**: 2026-04-21  
**阶段**: 第一阶段 (A)  
**状态**: 设计中

## 背景与目标

### 当前问题
- 用户每次发布拼车信息都需要重复填写相同的出发地、目的地等信息
- 对于固定通勤路线的用户,发布效率低,体验差
- 缺少快捷操作入口,无法快速复用历史信息

### 目标
- 降低发布门槛,提升发布效率
- 支持历史行程一键复用
- 支持常用地点管理和快速选择
- 提升用户活跃度和发布频率

### 非目标
- 不做智能推荐算法(留待后续优化)
- 不做行程模板系统(避免功能重叠)
- 不改变现有表单验证逻辑

---

## 功能设计

### 1. 快速复用上次行程

**功能描述**:
- 发布页顶部显示"使用上次行程"按钮
- 点击后自动填充上次发布的所有信息(出发地、目的地、类型、座位数、途径点、备注)
- 出发时间保持空白,需用户手动选择
- 填充后所有字段可自由编辑

**交互细节**:
- 按钮仅在有历史行程时显示
- 点击后按钮变为"已加载"状态,避免重复点击
- 新用户无历史时,隐藏该按钮

**数据来源**:
- 查询当前用户最近一条已发布的行程记录
- 从 `rides` 表读取,条件:`user_id = 当前用户 AND deleted_at IS NULL`
- 按 `created_at DESC` 排序取第一条

---

### 2. 历史行程列表

**功能描述**:
- 发布页显示最近 2-3 条历史行程卡片
- 卡片显示:出发地 → 目的地 + 发布日期
- 点击卡片自动填充该行程的所有信息
- 提供"查看更多历史"入口,打开完整历史列表

**交互细节**:
- 卡片点击后高亮显示当前选中状态
- 出发时间保持空白,需用户手动选择
- 填充后所有字段可自由编辑

**查看更多历史**:
- 点击后打开底部抽屉
- 展示完整历史列表,分页加载(每页 10 条)
- 支持按出发地/目的地搜索
- 点击任意历史记录后,关闭抽屉并填充表单

**数据来源**:
- API: `GET /api/rides/history?limit=3`
- 返回字段:id, type, departure, destination, departureTime, seats, waypoints, note
- 按 `created_at DESC` 排序

---

### 3. 常用地点管理

**功能描述**:
- 用户可预先在个人中心配置常用地点(家/公司/学校等)
- 发布时选择地点后,可快速保存为常用地点
- 常用地点按使用频率自动排序
- 发布页地点选择器显示最常用的前 5 个

**常用地点管理页**:
- 位置:个人中心 → 常用地点
- 功能:添加、编辑、删除常用地点
- 列表按使用次数降序排列
- 显示:地点名称、详细地址、使用次数

**发布页地点选择**:
- 点击出发地/目的地输入框,弹出地点选择器
- 顶部显示常用地点快捷按钮(最多 5 个,按使用频率排序)
- 点击常用地点直接填充,同时使用次数 +1
- 也可选择"地图选点"或"手动输入"

**首次保存常用地点**:
- 用户首次选择某个地点后,弹窗询问"是否保存为常用地点?"
- 用户可输入名称(如"家"、"公司")并保存
- 保存后该地点出现在常用地点列表

**数量限制**:
- 不限制常用地点数量
- 按使用频率自动排序
- 发布页只显示最常用的前 5 个

## 技术架构

### 数据模型

**新增表:favorite_locations**

```sql
CREATE TABLE favorite_locations (
  id INT PRIMARY KEY AUTO_INCREMENT,
  user_id INT NOT NULL,
  name VARCHAR(50) NOT NULL COMMENT '地点名称',
  address VARCHAR(200) NOT NULL COMMENT '详细地址',
  latitude DECIMAL(10,7) COMMENT '纬度',
  longitude DECIMAL(10,7) COMMENT '经度',
  use_count INT DEFAULT 0 COMMENT '使用次数',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_use_count (user_id, use_count DESC)
);
```

**复用现有表:rides**
- 历史行程直接查询 `rides` 表
- 条件:`user_id = 当前用户 AND deleted_at IS NULL`
- 新增索引:`INDEX idx_user_created (user_id, created_at DESC)`

## 交互流程

### 页面加载流程

```
用户进入发布页
    ↓
并行请求:
├─ GET /api/rides/history?limit=3
└─ GET /api/favorite-locations
    ↓
渲染页面:
├─ 有历史 → 显示"使用上次行程"按钮
├─ 显示历史行程卡片(2-3条)
└─ 缓存常用地点数据
```

### 填充历史行程流程

```
用户点击历史行程卡片
    ↓
读取该行程数据
    ↓
填充表单字段(出发时间除外)
    ↓
卡片高亮显示
```

### 常用地点使用流程

```
用户点击出发地/目的地输入框
    ↓
弹出地点选择器
    ↓
显示常用地点快捷按钮(前5个)
    ↓
用户选择:
├─ 点击常用地点 → 填充 + use_count +1
├─ 地图选点 → 选点成功 → 询问是否保存
└─ 手动输入 → 输入完成 → 询问是否保存
```

### 发布提交流程

```
用户点击"立即发布"
    ↓
表单校验
    ↓
POST /api/rides
    ↓
后端处理:
├─ 创建行程记录
└─ 检测并更新常用地点 use_count
    ↓
发布成功 → 跳转
```

## 实现细节

### 后端实现要点

1. **FavoriteLocation 模块**
   - 新增 Entity、Controller、Service
   - 关联 User 实体(一对多关系)
   - 实现 CRUD 接口和使用计数接口

2. **历史行程查询优化**
   - 在 RideService 中新增 `getMyHistory()` 方法
   - 只返回必要字段,减少数据传输
   - 添加数据库索引优化查询性能

3. **常用地点使用计数**
   - 发布行程时,检测出发地/目的地是否匹配常用地点
   - 使用地理坐标距离计算(误差 < 100m 视为匹配)
   - 匹配成功则调用 `incrementUseCount()`

### 前端实现要点

1. **状态管理**
   - 使用 ref 管理表单数据
   - 缓存历史行程和常用地点数据
   - 标记是否已从历史加载

2. **组件通信**
   - 子组件通过事件向父组件传递数据
   - 父组件监听事件并更新 formData

3. **性能优化**
   - 数据在 onShow 时加载并缓存
   - 搜索输入使用防抖
   - 历史行程抽屉使用虚拟滚动(数据量大时)

### 错误处理

1. **网络异常**
   - API 调用失败显示 Toast 提示
   - 历史行程/常用地点加载失败不影响正常发布

2. **数据校验**
   - 填充历史行程后仍需校验必填字段
   - 常用地点名称不能为空,不能重复

3. **边界情况**
   - 新用户无历史时隐藏快捷操作区
   - 无常用地点时只显示地图选点和手动输入

## 风险与权衡

### 风险

1. **数据同步问题**
   - 风险:用户在多设备使用时,常用地点可能不一致
   - 缓解:存储在后端数据库,天然支持跨设备同步

2. **地点匹配准确性**
   - 风险:地理坐标匹配可能误判
   - 缓解:设置合理的距离阈值(100m),允许用户手动调整

3. **历史行程数据量**
   - 风险:长期用户历史记录过多,查询性能下降
   - 缓解:添加数据库索引,分页加载,只显示最近记录

### 权衡

1. **自动填充 vs 手动选择**
   - 决策:采用手动点击触发,而非自动填充
   - 理由:避免误操作,给用户更多控制权

2. **常用地点数量限制**
   - 决策:不限制数量,按使用频率排序
   - 理由:不同用户需求差异大,智能排序可解决选择效率问题

3. **历史行程时间范围**
   - 决策:不限制时间范围,显示所有历史
   - 理由:用户可能需要复用很久之前的行程,搜索功能可解决查找问题

## 后续优化方向

1. **智能推荐**
   - 根据时间段、星期、历史行为预测用户需求
   - 自动推荐最可能的行程(如周一早上推荐"家→公司")

2. **行程模板**
   - 允许用户将常用路线保存为模板
   - 模板可包含更多自定义信息(价格、备注模板等)

3. **语音输入**
   - 支持语音输入地点名称
   - 提升填写效率

4. **地点智能识别**
   - 自动识别高频地点并建议保存
   - 减少用户手动配置成本
